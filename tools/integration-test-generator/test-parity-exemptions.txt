# Engine test-parity exemptions.
#
# Read by tools/integration-test-generator/tests/engine_test_parity.rs, which
# runs under `cargo test --workspace`.
#
# GH #196/#195: java.java.jinja and kotlin.kt.jinja each have one whole
# duplicated test program per SQL engine branch. An assertion added to one
# branch (almost always postgresql, the richest branch) reaches none of the
# others, and the branches drift apart silently -- the Redshift branches in
# particular ended up with fewer than half the postgresql branch's test
# functions. This file is the parity gate's ratcheting allowlist, modeled on
# coverage-exemptions.txt: it ratchets in BOTH directions and there is no
# tolerance mode.
#
#   * a (template, engine) branch missing a test function the postgresql
#     branch of the same template has, with no entry here, fails the build
#     (regression -- the drift got worse);
#   * an entry here for a test function the branch now DOES have also fails
#     the build (stale -- the gap was closed, delete the line).
#
# Format: <template>|<branch>|<test-function-name> : <reason>
#
# <branch> is the key engine_test_parity.rs's `derive_branch_key` derives for a top-level
# template branch: for most branches that is a literal SQL engine name (`mariadb`), but for a
# branch conditioned on driver or backend instead of (or in addition to) engine, it is every
# quoted literal the condition compares against, joined with `-` in source order --
# `driver == "r2dbc" and engine == "postgresql"` keys as `r2dbc-postgresql`, and
# `backend == "kotlin-exposed"` keys as `kotlin-exposed`.
#
# The `duckdb`/`mariadb`/`mssql`/`mysql`/`oracle`/`redshift`/`snowflake`/`sqlite` entries below are
# structural: "no equivalent query exists in <engine>'s queries/*.sql fixture" -- the
# postgresql-only test calls a generated Queries method (a UserStatus enum parameter, or a
# nullable composite-column read for board #197) that has no equivalent query defined for this
# engine at all. Closing this requires designing a per-engine equivalent query, not copying an
# assertion.
#
# The other reason shape this file used to carry -- "the underlying query
# already exists in this engine's queries fixture but the harness branch was
# never wired up to call it" -- named a closeable coverage gap rather than a
# structural incompatibility. All entries of that shape have been closed by
# porting the missing test into each branch (GH #196/#195 follow-up); none
# remain here as of this writing. A future PASS gap of that shape would look
# identical to a structural one syntactically -- check the query fixture
# before assuming it belongs in this file at all.
#
# This follow-up made the gate measure two more branches it previously missed entirely (see
# engine_test_parity.rs's module doc), each with its own reason shape:
#
#   * `r2dbc-mysql-mariadb` (java.java.jinja/kotlin.kt.jinja `driver == "r2dbc" and (engine ==
#     "mysql" or engine == "mariadb")`) has no generated project today --
#     tools/integration-test-generator/src/main.rs:657-687 wires `driver == "r2dbc"` only for
#     `engine == "postgresql"` (java-r2dbc, kotlin-r2dbc) and kotlin-exposed. Every gap in this
#     branch is recorded, not closed, so the deficit isn't silently discarded; delete these entries
#     the day a java-r2dbc-mysql/-mariadb or kotlin-r2dbc-mysql/-mariadb project is wired there --
#     do not port a test into this branch before that, since nothing would ever run it.
#   * `r2dbc-postgresql` (`driver == "r2dbc" and engine == "postgresql"`) IS wired
#     (integration_tests/java-r2dbc, integration_tests/kotlin-r2dbc) and is missing exactly one
#     test each: see the entries below for why.
#
# Blank lines and lines starting with `#` are ignored.
