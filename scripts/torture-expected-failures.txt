# Expected-failure allowlist for scripts/check-generated-backends.py.
#
# Keyed by integration_tests/ project directory name (not backend name --
# several projects share a backend, e.g. typescript-pg-structs-only and
# typescript-pg both use backend "typescript-pg", and only one of them
# fails against the torture schema, so backend name is not a unique key).
#
# The script fails the build in BOTH directions:
#   - a project below fails that is NOT listed here -> regression, investigate
#   - a project below is listed here but PASSES -> this list is stale, delete
#     its line (the underlying defect was fixed)
#
# Format: "<project> : <one-line reason> (<issue ref>)". Blank lines and
# lines starting with # are ignored. Reasons are grouped by root cause, not
# alphabetically, so the three defect classes stay visible as classes.

# --- Defect A: a quoted SQL identifier (e.g. "widgetId") is embedded
# unescaped into a host-language string/byte literal that itself uses double
# quotes as its delimiter, terminating the literal early and cascading into
# unrelated-looking compiler errors. This is issue #179 (the open successor
# to the closed #150) -- the torture schema's quoted mixed-case "widgetId"
# primary key is simply the first fixture that reaches it. The escaping layer
# is landing per language rather than all at once, so these go stale a few at
# a time -- elixir-ecto and elixir-postgrex already have.
rust-sqlx : SQL string literal embeds unescaped "widgetId", breaks the Rust string/sqlx macro (#179)
rust-sqlx-nested-json : same as rust-sqlx -- shares backend rust-sqlx (#179)
rust-tokio-postgres : same defect, tokio-postgres query string (#179)
csharp-npgsql : same defect, C# string literal (#179)
go-pgx : same defect, Go string literal (#179)
ruby-pg : same defect, Ruby string literal (#179)

# --- Defect B: a word reserved in the target language (`class`, from
# sql/torture/schema.sql's "class" column) is emitted unescaped as a field,
# parameter, or local name. This is issue #180 (open successor to the closed
# #151); the TypeScript entries are also issue #215, which covers column
# names that are not valid JS identifiers across all 12 TS backends.
#
# The three JVM entries that used to sit here (java-jdbc, kotlin-jdbc,
# kotlin-jdbc-ext) are gone, and their reason was misattributed while they
# lived here: `class` is in both JVM manifests' `reserved` list and was always
# escaped. What actually failed was the reader defect behind #191/#213/#214 --
# the torture schema's composite `home_address` and uuid `external_id` columns
# were read through the untyped `getObject`, whose Object/Any static type is
# assignable to nothing. Fixing that made all three build.
typescript-postgres : "class" column becomes an unescaped TS function parameter name (#180, #215)
typescript-pg : same as typescript-postgres -- shares backend typescript-pg (#180, #215)
typescript-pg-zod : same as typescript-postgres -- shares backend typescript-pg (#180, #215)
typescript-pg-zod-outer-join-unions : same as typescript-postgres -- shares backend typescript-pg (#180, #215)
typescript-pg-outer-join-unions : same as typescript-postgres -- shares backend typescript-pg (#180, #215)
typescript-kysely : same defect, Kysely query builder call parameter (#180, #215)

# Defect C (#200) -- `array<T>` emitted into a PHP native type position, which
# has no generic syntax -- is fixed. The three php entries that lived here are
# deleted rather than kept "just in case": this file is a gate in both
# directions, and a listed project that passes fails the run.
